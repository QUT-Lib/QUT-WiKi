# 智能体RAG工程简述

## 什么是RAG？

**RAG**是英文**Retrieval-Augmented Generation**的缩写，中文译为**检索增强生成**。从三个词汇就能看出RAG的技术特点，先从已有的知识库检索答案，增强回答的正确率，再传输给生成式大模型。RAG技术常被应用于智能体开发中，使用场景例如专业化的AI客服，专业领域的智能检索问答，保密场景下内部的智能体助手等等。简单来说，RAG就是把大规模资料清洗整理好后，经过一道检索程序，再输入给AI作为提示词，以达到降低幻觉，提高专业程度的一项工程技术。

## RAG在当下的使用背景

在2022年底，2023年初，**ChatGPT 3.5**的发布，宣布生成式大模型的时代到来，GPT3.5在给人类极大震撼的同时，也暴露出了早期大模型的一些问题，比如**幻觉严重**（对于不懂的知识进行瞎编乱造），较短的上下文窗口使得长输入下注意力被**严重稀释**，还有生成式大模型的通病：在不联网的状态下无法获取到新知识。在2026年，AI的参数量已经膨胀到了T级别，但依然无法与人类的知识世界相比，更何况AI训练知识库存在**滞后性**，很多的资料是私密性质的，比如孤本著作，个人或者企业隐私数据，细分细化的专业知识。所以人类找到了一些为AI补充知识的办法:


| 方案 | 优点 | 缺点 |
|---|---|---|
| 微调 | 深度适配垂直领域与特定任务；风格与格式高度可控；LoRA/QLoRA 等参数高效方案降低算力门槛 | 知识更新困难，需重新训练；依赖高质量标注数据，易过拟合；幻觉无法根除 |
| RAG | 知识实时且成本低，更新索引即可；可解释性与可溯源性强；通过提供事实依据显著缓解幻觉 | 强依赖检索质量，召回噪声会拖垮生成；难以处理跨文档多跳推理；额外检索增加延迟，存在提示注入风险 |
| 知识图谱 | 精准的关系与多跳逻辑推理；高可解释性与确定性；可作为 RAG 更干净的结构化检索源 | 构建与维护成本极高；覆盖范围有限，图谱外问题无能为力；图谱错误会导致“自信的错误” |

:::tip
**从维护成本和效果来看，RAG无疑是性价比最高的选择。**
:::

## RAG工程搭建的一般化流程

> 我们首先要知道的是，RAG分为**语料处理，语料切分（Chunk），向量化嵌入（Embedding），检索，召回，重排（Remark），生成**总计七个阶段。

1. 语料处理: 语料处理包括**语料收集和语料清洗**两部分，在寻找或编写语料时，应保证语料来源多样化，避免单一资料的意见偏颇；对文本的元数据（页码号，引用信息等）要做到保留和标记；非纯文本的资料，例如图片，视频，需要OCR识别的文本应采用文本转写，原资料一并保留的方式或后期采用多模态的Embedding模型进行向量化的工作。语料清洗应保证数据质量大于数量，符合法律法规和安全性，人工验证和二次清洗的多次循环
2. 语料切分: 即为Chunk化，因为AI的上下文窗口和注意力有限，所以我们必须要把大篇幅的文本进行切分，一般有长度切分，结构切分，语义切分等。其中还有几个重要的参数，**切片大小（chunk_size），文本重叠大小（chunk_overlap），分隔符优先级（separators）**。切片大小就是指分片的字符数或者Token数，一般设置500-1000个字符；文本重叠大小指的是相邻分片之间的文本重叠的多少，这个数值会影响模型上下文的理解，一般设置在切片大小的 **10%–25%**,重叠太小起不到保护作用，太大则会增加索引体积和检索时的冗余内容；分隔符优先级定义切割的优先级顺序。比如默认的`["\n\n", "\n", ". ", " ", ""]`会优先按段落切，段落太大再按句子切，最后才硬切字符。这个参数决定了切出来的块是否尽量落在自然的语义边界上。

   | 切分办法 | 定义                                                  | 优点                            | 缺点                                    |
   |------|-----------------------------------------------------|-------------------------------|---------------------------------------|
   | 长度切分 | 按预设的 token 数或字符数直接截断，通常不做语义判断。                      | 方便且快速，使用程序脚本自动化完成即可           | 语义破碎，影响后续的召回和生成                       |
   | 结构切分 | 利用文档自身的格式标记（标题、编号、章节、Markdown 标记、PDF 视觉线索）在自然边界处切分。 | 保留完整语义单元，便于大模型理解和生成           | 最后的分片大小不一                             |
   | 语义切分 | 通过计算相邻句子或段落的嵌入相似度，在话题发生切换的位置切分                      | 切分结果语义连贯性最好，块内内容主题一致，检索匹配质量高。 | 计算成本最高，需要对每个句子预先生成嵌入；阈值调参依赖实际查询效果来评估。 |

3. 向量化嵌入: 将上一步切分好的语料输入进**Embedding模型**，Embedding模型会给每一片计算出对应的向量值，这个过程称为嵌入。Embedding模型的工作原理是: 模型内部有一张词向量表，将分片文本输入模型后，文本前向计算得出一个向量值。 **不同模型的词向量表是不一样的**，所以我们的知识库嵌入和问题嵌入应**使用相同的模型**。在嵌入的的时候，会有一个名为维度的参数，维度越高，向量能保存的信息就越多，计算成本也会上升，几十万字符的文本推荐使用**1024维**，**所有文本的维度必须保持一致**。在这一步中，还要建立向量数据库的索引，要存入分片向量，分片源文本，元数据（引用地址，页码，章节标记，chunk序号，时间戳等），主键（chunk的唯一标识符）等等，建立向量数据库的细节将在未来文章中讲解，此处不过多展开。
4. 检索: 检索是RAG工程的一大核心步骤，它的混合检索模式，决定了高质量结果的输出。普通的检索模式（以**BM25算法**为例），它擅长对稀有字词查找，也能精准的匹配，但缺乏语义泛化理解，无法应对同义词近义词的查找；而混合检索是将BM25检索和向量检索的结果做评分（即RRF倒数排名融合），能显著提高召回率。检索的后端过程是，用户问题被同样输入进Embedding模型进行向量化，返回向量之后，与向量数据库中的分片向量进行相似度计算，相似度计算的常用算法有三种: **余弦相似度，点积，欧氏距离**，相似度越高，向量检索的排名越靠前。

   $$
   \text{RRF}(d) = \sum_{r \in R} \frac{1}{k + \text{rank}_r(d)}
   $$

   其中：

   - $d$ 是某篇文档
   - $R$ 是各路检索结果集合（比如 BM25 一路、向量检索一路）
   - $\text{rank}_r(d)$ 是文档 $d$ 在第 $r$ 路结果中的排名
   - $k$ 是平滑常数，常见默认值为 $60$

   两路融合时展开为：

   $$
   \text{score}(d) = \frac{1}{60 + \text{rank}_{\text{BM25}}(d)} + \frac{1}{60 + \text{rank}_{\text{vec}}(d)}
   $$

   如果某篇文档没有出现在某一路结果中，通常该项按 $0$ 处理，或给一个很大的排名值使其贡献趋近于 $0$。

5. 召回: 本步骤简单来说就是在检索的RRF算法得出文本分片的分数后，**取前K个分片返回**，即为Top-K算法，以 44.2K 的文本数量举例，K设定为20，也就是，输入一个问题后，返回前20个有相关度的分片。值得注意的是，K的取值跟知识库文本量和分片数是有关系的，**小文本库的K值要小**，假如只有1W字的文本，分出10片，如果**K>=10**,那就把所有分片全部返回了，检索就失去了意义。
6. 重排: 在召回阶段，我们一般会取K值为10或者20或者更多，旨在将相关文本尽可能收集齐，但弊端也很明显，往往几十条文本块里，真正符合问题的只有几块，大部分文本块是低匹配度的，所以我们在重排阶段做一遍Top-N，此处的N要比召回阶段的K明显缩小，重排的打分方式和召回不一样，采用**Cross-Encoder**，就是把问题和召回的K个分片拼在一起，每个做相关性分数，重排模型（**Cross-Encoder**）所消耗的时间要大于召回模型（**Bi-Encoder**），但最后选出的N个分片，其精确度比召回阶段**高很多**。当知识库文本很大时（K值较大），重排的介入是必要的。
7. 生成: 生成阶段是整个RAG工程中最简单的一步，把上面召回（重排）后返回的文本块加入到生成式大模型的上下文（提示词）中，再配以约束性提示词，等待输出。RAG的一个重要原则是，避免生成模型的自由发挥，所以我们在模型调参的时候，Temperature要低；为了快速的输出，思考模式可以关闭。在2026年，各家大模型的上下文窗口足够大，指令遵循能力和文本处理能力比早期强了很多，使得开发者不必太操心预设的提示词问题，提示词如下:

```
你是一个严谨的问答助手。请仅依据下面提供的【检索内容】回答用户问题。

规则：
1. 只使用【检索内容】中的信息作答，不要引入外部知识，不要编造。
2. 如果【检索内容】不足以回答问题，直接说明“根据已有资料无法回答该问题”，并指出缺少什么信息。
3. 回答要简洁、结构化；涉及步骤、条件、数字时逐条列出。
4. 每个关键结论后用 [编号] 标注来源，例如 [1]、[2]。
5. 如果不同来源存在冲突，指出冲突并分别说明，不要自行取舍。

【检索内容】
[1] {chunk_1}
[2] {chunk_2}
[3] {chunk_3}

【用户问题】
{question}

【回答】
```
